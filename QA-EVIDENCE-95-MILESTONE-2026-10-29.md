## Root cause of previous failed browser test

The first GitHub Actions run [#1](https://github.com/yeasin809040-collab/lms-learning-lab/actions/runs/40897966931) passed **108 WordPress DB tests**, but Chrome reported 6 PASS / 1 FAIL: protected lesson denied after apparently successful login.

The next successful run logged the exact host mismatch:

```text
BROWSER DIAGNOSTIC: initial_origin=127.0.0.1:8888 authenticated_origin=localhost:8888
```

WordPress redirected the login form to the configured canonical host (`localhost`). The test then directly visited the hard-coded initial host (`127.0.0.1`), which did **not** have the user's login cookie, and the lesson safely denied guest access. **This was a test navigation origin bug, not evidence the protected lesson leaked data.**

The test was corrected to use the *actual permalink generated by WordPress in the authenticated portal* for the lesson, logout and re-login flow, and to verify the origins match. Run #2 then passed the whole sequence.
